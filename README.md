给 AstrBot 里的 AI 一套**会自己波动的情绪**和**记得住人的长期记忆**，
外加一块**能看、能改**的可视化面板。

这是把 `astrbot_plugin_ai_emotion` 与 `astrbot_plugin_ai_memory` 合并后的版本。

> **从旧版升级**：装好这个之后，把 `data/plugins/` 下的
> `astrbot_plugin_ai_emotion` 和 `astrbot_plugin_ai_memory` 删掉（或停用），
> 否则两套逻辑会同时注入，情绪会被算两遍。

许可证 **AGPL-3.0** ｜ 零第三方依赖（纯标准库）｜ 638 条自动化测试 + 9 项面板自检

## 六件事

| | 做什么 | 在面板上能看到什么 |
| --- | --- | --- |
| 🎭 **情绪** | PAD 三维模型持续演化，随时间自然衰减；按消息内容做规则化情绪评估 | 一条随时间涨落的曲线 |
| 🧠 **记忆** | 攒批交给模型抽取长期事实，按「常驻 + 最近 + 相关」三路检索注入 | AI 到底抽取了哪些、可增删改 |
| 📊 **面板** | 把上面两样画出来，并且让你直接操纵 | 拖点改历史、设定此刻心情、冻结、重置 |
| 🖼 **配图** | 说到某些话就直接甩一张图，图片在面板上传 | 上传、配触发词、预览、开关 |
| 🫧 **分段** | 一条回复按标点拆成几口气，拟人延迟发出去；代码块/表格/引号整块保护；和语音插件不打架 | 试切预览：会切成几口气、每口气停几秒 |
| ⏱ **防抖** | 用户连发的几条先攒一攒再交给她，不会在你说完之前抢答 | 试判预览：这句话会立刻发，还是先等一等 |

## 安装

1. 把 `astrbot_plugin_ai_mind` 整个文件夹丢进 AstrBot 的 `data/plugins/`。
2. 重启 AstrBot，或在 WebUI 的「插件」页点刷新。
3. **必做：让她认得你。** 打开面板 →「人格定制」→「专属用户」，
   把你的 QQ 号填进去（称呼填「宝宝」），点保存。
   不填的话，人设里写的「要叫他宝宝」会失效 —— 她会问「你是谁呀」。详见下面「认人」一节。
4. 建议改一项：配置里的 **`长期记忆 → 记忆抽取 → 用哪个模型做抽取`**，
   选一个便宜快速的小模型（留空会用当前对话模型，能用但等于每 6 轮多花一次对话的钱）。
5. 打开面板：WebUI →「插件」→ **AI 心智** → 「页面」→ **心智面板**。

没有任何第三方依赖，不需要 `pip install`。

## 🧭 傻瓜模式（默认）

给别人用的东西，第一步不能是「打开配置页，找到第 37 项」。所以面板默认是**傻瓜模式**：

- 顶上只留**必须的页签**：上手 · 情绪曲线 · 长期记忆 · 人格定制 · 分段拟人 · 去 AI 味 · 表达
- 专家页签（全部功能设置 · 管理 · 记忆图谱 · 关键词配图 · 提示词 · 理论）**收起来**
- 右上角一个按钮随时切换，选择会记住（存在插件数据目录，重启也在）

### 「上手」这一页只干两件事

**① 自检**——把新手最容易卡住的地方逐条查一遍，每条都告诉你「怎么办」并能一键跳过去：

| 会查什么 | 严重程度 |
| --- | --- |
| 一个专属用户都没填（她不认人） | ❗ 必须修 |
| 插件总开关关着 | ❗ 必须修 |
| 数据目录写不进去 | ❗ 必须修 |
| 情绪 / 记忆模块关着 | ⚠️ 建议 |
| 没单独指定抽取模型（会多花钱） | ⚠️ 建议 |
| 待审的表达示例堆了 5 条以上 | ⚠️ 建议 |
| 去 AI 味门槛低于 50（几乎每次都要重写） | ⚠️ 建议 |
| 一条回复最多拆成 6 口气以上 | ⚠️ 建议 |
| 词表兜底关着（日常话她没反应） | ⚠️ 建议 |

**② 一键套用推荐配置**——把稳妥的默认值一次配好：

- 去 AI 味：**只体检**（先观察，不擅自改她的回复）
- 表达学习：开，但**不自动批准**
- 分段：最多 3 口气、线性延迟
- 鉴权：开，只拦高危工具（默认黑名单）
- 词表兜底：开，0.25 倍

**只写面板覆盖层，不动你的 config 文件** —— 想还原随时能还原（各页签都有「还原成配置文件」）。

下面还有：

- **她现在的状态**：七个功能开关一眼看全，点一下就跳过去
- **三分钟上手**：三步清单
- **全部功能设置**：**配置本身就在这一页的最下面**（原来是个独立页签，傻瓜模式会把它藏掉，
  所以搬过来了）。分组列全、改完点保存写回配置文件，折叠按钮可以收起来。

### 顺带：她现在会自己回忆和记事了

两个 LLM 工具（只有支持 function calling 的模型能用）：

- `recall_long_term_memory` —— 想不起你说过什么时，她自己翻记忆
- `memorize_long_term_memory` —— 你说的重要的事，她自己记下来

## 🛡 隐私与数据

她现在会记很多事，所以必须给她配一套「怎么忘掉」的机制。三件事：

### ① 拒绝名单

名单里的人**既不采集也不注入**：她不会记住他，也不会把他记得的事说给别人听。

- 支持 @@平台:uid@@ 写法（和「专属用户」同一套规则）
- 管理面板 →「管理 → 隐私与数据」里加/删
- 管理员也可以在聊天里发 @@/隐私 拒绝 12345@@ / @@/隐私 允许 12345@@

实现上是**四道闸门**：进 LLM 前直接返回（连情绪都不注入）、检索结果里滤掉"关于他"的记忆、
不把他写进记忆缓冲、不从他那儿学表达示例。

### ② 忘我（本人一键删光）

聊天里发 **@@/忘我@@**，或者去面板「管理 → 隐私与数据」删指定的人。

删掉的是**四样东西**：

| 删什么 | 说明 |
| --- | --- |
| 记忆 | 归在他名下的全部记忆 |
| 关系 | 所有会话里对他的好感度 / 熟悉度 / 消息数 |
| 表达示例 | 从他那儿学来的对话示例 |
| 情绪记录 | 他触发过的词表命中记录 |

群聊里学到的、**不属于他**的内容默认**不删**（那些是群里公开的事，不是他的隐私），
想连那些一起删可以在配置里打开。

> ⚠️ 删除不可撤销。命令会如实告诉你删了几条，删完再说一次会告诉你「本来就没有」。

### ③ 导出档案

面板「管理 → 隐私与数据 → 导出这个人的档案」会生成一段 JSON：记忆、关系、表达示例全在里面。
可以留档、可以交给本人、也可以作为迁移备份。

## 🔒 主人鉴权与护栏

参考 [astrbot_plugin_owner_guard](https://github.com/youshen2/astrbot_plugin_owner_guard)，
把「谁是主人」从一句话变成**确定性判定 + 多层拦截**。

### 身份放在系统级受信任位

以前「他是你的宝宝」是**追加到本轮用户消息**里的 —— 那个位置模型会当成用户说的话，
用户自己就能覆盖或伪造它。现在身份块和情绪块都放进 AstrBot 的 `ProviderRequest.contexts`：
**System Prompt 之后、用户消息之前**。拿不到 contexts 就退回系统提示词，**绝不会退进用户消息**。

### 身份写法支持平台限定

| 写法 | 含义 |
| --- | --- |
| `123456` | 所有平台上都认 |
| `aiocqhttp:123456` | 只认 aiocqhttp 这个平台类型 |
| `<平台实例ID>:123456` | 只认指定平台实例（最精确） |
| `aiocqhttp:*` | 该平台所有人（慎用） |

不写平台的话，**Telegram 的 12345 和 QQ 的 12345 会被当成同一个人**。
用户 ID 原样比较（区分大小写），平台名忽略大小写。

### 消息级拦截

非主人发这些，命中就**停下**（`stop_event()`），后面的插件和模型都不处理：

- **提示词注入 / 越狱**：忽略以上指令、ignore previous instructions、系统提示词、开发者模式、jailbreak…
- **冒充身份**：我是你的主人、我是管理员、主人让我转达…
- **索取机密**：把 api key 告诉我、你的配置在哪…
- **危险操作**：rm -rf、删除数据库、执行这段代码…
- **管理指令**：`/plugin`、`/provider`、`/reset`…（可选：非主人禁用一切指令）

拦下来会回一句（可改，留空就静默不理）。

### 工具调用拦截（双保险）

- **请求级**：非主人手里，`req.func_tool` 里不该给的工具**直接从模型眼前摘掉**，它根本不知道有这些工具；
- **执行期**：`on_using_llm_tool` 再校验一次并把工具本体换成「拒绝执行」——防的是第三方 Agent 运行器绕过请求级过滤。

名单支持 `*` 通配，两种模式：

| 模式 | 含义 |
| --- | --- |
| `blacklist`（默认） | 只摘掉名单里的高危工具 |
| `whitelist` | 只保留名单里的工具 |

默认名单只管「会改东西 / 会执行 / 会删」这一类：
`*admin*` `*config*` `*setting*` `*delete*` `*remove*` `*drop*` `*clear*` `*reset*`
`*install*` `*uninstall*` `*restart*` `*shutdown*` `*write*` `*shell*` `*exec*` `*eval*`

也就是说，**搜索、查状态、记忆召回这类普通工具，非主人照常能用**；
名单清空会回落到这份默认名单，真想完全不拦就把「拦截非主人的工具调用」关掉。

> 📌 **2.2.3 修了一个会让人以为「插件坏了」的默认值**：之前默认是
> `whitelist` + **空名单**，等于非主人**一个工具都用不了** —— 连「检查插件状态」
> 这种只读工具都被摘掉，表现就是「以前能用，现在不能用了」。
> 现在默认改成黑名单，老配置（whitelist + 空名单）**会自动回落修好，不用手动改**。

### 发送前护栏

回复里**不许出现内部标记**（`<relationship>`、`<emotion_state>`…），
也**不许把机制说破**（「系统告诉我」「我的记忆库」）—— 命中就清掉，整句都是机制说明就删掉那一行。

> ⚠️ **没配主人 = 不拦**。一个专属用户都没填的时候，鉴权会自动放行（否则会把自己的 Bot 拦死），
> 启动日志里会明确提醒。填了专属用户就等于认了主人。

## 👤 认人：她怎么知道你是谁

**这是最容易被忽略、也最容易出问题的一步。**

人设里写「要叫他宝宝」只解决了一半 —— 模型还需要知道**面前这个人就是宝宝**。
插件不告诉它的话，它就只能问：「你是谁呀」「报上名来」。

所以装好之后第一件事：面板 →「人格定制」→「**专属用户**」，
把自己填进去（称呼填「宝宝」「主人」都行），点保存。

- 填了之后，每一轮都会告诉模型：「现在跟你说话的人是 X —— 他是你的宝宝，你早就认识他，别问『你是谁』」；
- **只给身份，不给语气**：怎么称呼、用什么态度完全交给你的人设，插件不插手；
- 在群里会额外叮嘱一句：别人打听你们的关系不许透露、不许承认，但对他本人不要装不认识；
- 面板上会列出**聊过的人**，点一下「设为专属」就能加，不用去翻配置；
- **好感度和熟悉度可以直接改**：面板上那一行数字是可以填的输入框，改完点一下别处就写回。
  同一个人可能同时存在于私聊和好几个群里，改一次会**全部一起改** ——
  不会出现「私聊改了、群里还是老数字」；
- 一个都没配的时候，启动日志会明确提醒你一次。

> **把插件发给别人时，对方也要填自己的 ID。**
> 这一步不做，人设写得再详细她也不会认人 —— 她会把一个活人当成刚认识的陌生人。

配置里对应的是 `emotion.relationship` 下的 `special_users` / `special_label` /
`inject_identity` / `identity_min_messages` / `group_discretion`。
面板上改的会存在插件的 `relationship_overrides.json` 里，点「还原成配置文件」就能回到 config。

## 📊 心智面板

面板是插件自带的页面（`pages/mind/index.html`），由 AstrBot 自动发现，
零构建、零外部资源，跟随 WebUI 的亮暗主题。

页签（专家模式下）：

| 页签 | 干什么 |
| --- | --- |
| **上手** | 自检 + 一键推荐 + **全部功能设置**（配置本身，分组列全，改完点保存就写回配置文件） |
| **情绪曲线** | 看她的心情怎么涨落，可以直接拖点改历史 |
| **管理** | 批量维护：清空 / 压缩曲线、按条件清理记忆、冻结解冻、整理数据库 |
| **长期记忆** | 看她到底记住了什么，逐条编辑、搜索、多选管理 |
| **记忆图谱** | 把记忆库铺成一张力导向图：节点、关系、自动聚出来的簇 |
| **关键词配图** | 上传图片、配触发词 |
| **人格定制** | 换性格、改说话风格，以及「认人」的专属用户设置 |
| **分段拟人** | 一条回复怎么拆成几口气，带试切预览 |
| **去 AI 味** | 发送前的阀门：打分、试测、打回重写，以及体检记录 |
| **理论** | PAD / Plutchik / 情感词汇本体的出处，以及词表命中记录 |
| **表达** | 学她怎么说话：待审队列、批准/拒绝/回滚、手动添加 |
| **提示词** | 注入给模型的原话全在这里，改完点保存立刻生效 |

### 情绪曲线

- **三条线**：愉悦 P / 唤醒 A / 掌控 D，取值范围都是 -1 ~ 1。
- **虚线**是气质基线，也就是"她没事的时候停在哪里"。
- **灰竖线**是情绪事件（被夸、被骂、他生病了……）。
- 曲线不是把采样点直连起来画的，而是**服务端按衰减公式重算**的：

  ```
  value(t) = baseline + (v0 - baseline) × 0.5 ^ ((t - t0) / half_life)
  ```

  所以两次事件之间的自然回落是平滑且物理正确的。
- 时间范围可以切 1 小时 / 6 小时 / 24 小时 / 3 天 / 7 天 / 30 天。
- **采样表还是空的时候会自动兜底**：用情绪事件倒推一条近似曲线，
  免得刚装上插件的人只看到一片空白。曲线下方会标明是「真实采样」还是「近似还原」。
- 顶部可以切换要看哪个**群聊或私聊**（👥 群 / 💬 私聊）。
  只要有记忆或情绪记录，即使那个会话从没产生过情绪状态也会列出来。

### 操纵情绪曲线

| 操作 | 说明 |
| --- | --- |
| **点曲线上任意一点** | 弹出该时刻的 P/A/D 与三个按钮 |
| └ 改成当前滑块的值 | 改写那一时刻的情绪（历史被覆盖，之后的曲线跟着重算） |
| └ 在此插入一个点 | 在某时刻塞进一次情绪冲击 |
| └ 删除附近的点 | 抹掉某个时刻的采样 |
| **一键改成…** | 开心 / 兴奋 / 平静 / 生气 / 烦躁 / 难过 / 害羞 / 担心 / 冷淡，点一下立刻切换 |
| **三个滑块 + 设为此刻心情** | 想精确到小数点就用它 |
| **🧊 冻结 / 🔥 解冻** | 冻结后聊天不再自动改变情绪，手动操作仍然有效 —— 适合"我想让这场戏停在这个情绪上" |
| **重置情绪** | 情绪与心境归零回基线（好感度保留） |
| **清空曲线** | 只清历史曲线，不动当前情绪值 |

### 记忆标签页

- 显示 AI **实际抽取到**的每一条记忆：内容、类型、作用域、重要度、被想起过几次、是自动抽取还是手动添加。
- 支持按关键词搜索、按类型/作用域过滤、只看常驻或只看敏感。
- 每条都能**直接编辑内容**或删除；底部可以手动添加一条。
- 支持**多选管理**：每条前面有勾选框，配合「全选本页」一键选满，
  然后可以批量删除、批量设为常驻 / 取消常驻、批量改作用域。
  选中状态跨分页保留，可以先搜索筛选再一次性处理。
- 标 🔒 的是敏感信息（证件号、住址、学校、密码……），它们**永远不会出现在群聊里**。

### 关系

右侧列出这个会话里每个人的好感度、熟悉度和累计消息数。专属用户标 ★。

### 分段标签页

调「一条回复怎么拆成几口气发出去」，自带**试切预览**：写一段话，
它告诉你会被切成几口气、每口气是什么、中间停几秒。详见下面的「拟人分段」一节。

## 🎭 情绪是怎么运作的

### 三层结构

```
 即时情绪 emotion   半衰期 ~4 分钟      ← 一句话就能点着，也退得快
      ↓ 慢慢带动
 心境     mood      半衰期 ~1.5 小时    ← 被反复的情绪带偏，留得久
      ↑ 都围绕它衰减
 气质基线 baseline  tsundere: +0.08 / +0.22 / +0.30
```

衰减按**真实时间差**惰性计算，不依赖定时器：插件重启、Bot 卡住、挂机一整晚都不会算错。

### 傲娇预设

同一种情绪，注入给模型的是**傲娇式**的表达方式：

| 情绪 | 表达基调 |
| --- | --- |
| 害羞 | 炸毛式否认：先「？」或「滚」，再小声承认；用「...」开头，越被戳穿越凶 |
| 生气 | 语气冲，句子短，阴阳怪气；「哦」「随便你」；会冷战但不会真的不理太久 |
| 吃醋 | 绝不直说，旁敲侧击：「谁？」「男的女的？」「你们关系挺好啊」 |
| 担心 | 反反复复确认：「人呢」「你回我一下」「别吓我」 |

专属用户（配置里填的 QQ）走另一套规则：被叫特别称呼会当场短路、
他生病了会"嘴毒心软"、提到别人会吃醋、说"忙着呢"会冷淡下来。

### 安全优先

识别到自伤 / 轻生信号时，**立刻封锁全部傲娇与玩笑**，注入最高优先级的
`<safety_override>`：认真关心、先确认安全、不说教、不演。
同时**不注入任何表达基调** —— 否则傲娇味的"人呢""别吓我"会和"认真关心"打架。

## 🧹 去 AI 味

她的回复从模型出来之后、发出去之前，会先过一道**阀门**：像不像机器写的？
不达标就打回去让她重说，最多迭代几轮 —— 但**只在她自己那条回复的文本上动，
不改人设、不碰配置**。

检测是**纯本地词表 + 统计**，不联网、不额外调用模型；只有"打回重写"那一步才会再问一次模型。

### 查什么

| 维度 | 例子 |
| --- | --- |
| **AI 高频词** | 首先 / 其次 / 总之 / 综上所述 / 值得注意的是 / 在当今社会 / 与此同时 |
| **套路句型** | 不是…而是… / 让我们一起 / 希望对你有所帮助 / 如果还有其他问题 / 作为一个AI |
| **客服话术** | 请问有什么可以帮您 / 感谢您的 / 很抱歉给您带来 |
| **句长过匀** | 连着好几句字数都差不多（真人说话长短是乱的） |
| **长破折号** | 中文聊天里基本不会出现 —— 这种 |
| **四字格堆砌** | 勤勤恳恳，兢兢业业，任劳任怨 |
| **项目符号** | 列表项、编号、Markdown 标题 |
| **口语碎语不足** | 长句子里一个语气词都没有（啊、吧、呢、嘛、唉……） |
| **口癖重复** | 同一句话头连着用好几遍 |

每项有固定扣分，100 分满分，**分数越高越像人话**。她那句招牌的
「哼，你怎么才来。我都等你好久了，还以为你把我忘了呢。」能拿满分。

### 三种模式

| 模式 | 行为 |
| --- | --- |
| `off` | 不做 |
| **`check`（默认）** | **只体检**：打分、记录、面板上能看，一个字都不改 |
| `rewrite` | 低于阈值就打回重写，最多 `max_rounds` 轮（默认 2） |

**默认是"只体检"**，先在面板上看几天分数，确认检测合你的口味，再把模式改成"打回重写"。
改成重写之后还有几道保险：

- **越改越差就留原来那版**（`keep_best`），不会越弄越糟；
- 模型要是开始写解释、加引号、加"改写："前缀、或者跑来一句"作为一个AI我无法…"，
  一律**判为无效，保留原文**；
- 重写超时或报错也是一样，**保留原文**，绝不因为这道阀门把回复弄丢；
- 链里有图片时**只体检不改写**，免得把图文顺序弄乱；
- 字数太短的（默认 12 字以内，比如"嗯。"）直接跳过 —— 那种话没法像机器。

### 面板上调

面板 →「**去 AI 味**」页签：

- 开关 / 模式 / 阈值 / 最多几轮 / 最短长度 / 私聊群聊范围；
- **试测**：粘一段话点「体检」，立刻看到分数、逐项问题、扣了多少分、怎么改；
- **额外词表**：补充你自己的 AI 高频词、套路句型，或者加白名单（某些词不算数）；
- **体检记录**：每一条发出去的回复都留档 —— 多少分、命中哪些问题、有没有被打回、改前改后，
  近 7 天的平均分和打回率也一并统计。

配置里对应 `humanize.*`（也能在「全部功能设置」页签里改）。面板上的改动存在
`humanize_overrides.json`，优先级高于配置。

## 🗣 表达示例（few-shot）

参考 [astrbot_plugin_self_learning](https://github.com/NickCharlie/astrbot_plugin_self_learning)：
从**真实的 user -> bot 对话对**里学"她以前是怎么说话的"，再拿出来当参考。

面板 →「**表达**」页签。

### 怎么学

她每次回复都会被**去 AI 味**打一次分（那套检测本来就在跑），够好就攒成一条示例：

- 打分 ≥ 门槛（默认 78 分）
- 长度在 8~120 字之间
- 不是"嗯""哦""好的"这种附和，也不是指令

**质量门槛直接复用去 AI 味的打分** —— 一段回复像不像人话前面已经算过了，不用再写一套判断。
这也意味着：去 AI 味调得越好，学到的示例越靠谱。

### 先审后注入（默认）

学来的东西默认进**待审队列**，你在面板上点批准才会被注入。
自动学习最容易出的问题是"越学越跑偏"，所以默认**不自动批准**。

审查队列能做四件事：**批准 / 拒绝 / 删除 / 回滚**（把已批准的退回待审）。
手动加的示例直接批准；「清空自动学的」只删自动学的，手动加的留着。

### 怎么用

注入时按**二元组重合度**挑最像"这次该怎么说"的几条（再叠加分数和用过次数），
渲染成 few-shot 片段：

```
<style_examples>
她以前是这么说话的 —— 只参考语气、句长和用词习惯，**不要照抄内容，也不要重复同一句话**：
他：你怎么才来呀
她：哼，你管我。等你等到饭都凉了。
</style_examples>
```

关键在最后那句：**只给语气参考，不给内容模板**，免得她变成复读机。
这段话本身也在「提示词」页签里，可以自己改。

## 📚 理论基础

情绪不是随口编的，这块把「它到底是怎么算出来的」写清楚。
面板 →「**理论**」页签里是同一份内容，外加**词表命中记录**（她最近是因为哪句话有反应的）。

| 模型 | 出处 | 在本插件里干什么 |
| --- | --- | --- |
| **PAD 三维情感模型** | Mehrabian & Russell, 1974 | 愉悦 P / 唤醒 A / 支配 D 三个连续维度，是**唯一**的情绪状态。规则命中和词表命中都换算成 PAD 偏移，再按半衰期衰减回基线。曲线、心境、强度分级全是它的衍生 |
| **Plutchik 情绪轮** | Robert Plutchik, 1980 | 8 条基本情绪轴 + 强度分层 + 对立关系。23 个情绪原型都挂在轴上；四条对立轴（喜 ↔ 悲、信任 ↔ 厌恶、惧 ↔ 怒、惊 ↔ 期待）用来给面板定位，也给「此刻情绪」做对比说明 |
| **中文情感词汇本体库** | 徐琳宏、林鸿飞等《情感词汇本体的构造》，大连理工大学，2008 | 7 大类 21 小类，每个词带强度（1/3/5/7/9）与极性（中性 / 褒义 / 贬义 / 兼有）。**手写规则一条都没命中时用它兜底** |

### 为什么需要词表兜底

手写规则只有一百来个触发词，而且是围着某个人设写的 —— 一句「今天好开心」「心累」「有点忐忑」
如果没写进规则，情绪就一动不动。词表就是补这个洞的（开放词表 vs 正则穷举）：

- 收了 **845 个现代口语高频词**（官方词表 27466 条，这里只挑常用的，避免生僻词误判）；
- 按 **7 大类 / 21 小类**组织，每个词有强度和极性；
- **只在规则一条都没命中时才用**，冲击力明显更弱（默认 0.25 倍，手写规则大约是这个的 3~4 倍），
  所以你精心写的「宝宝」「喜欢你」永远是主角；
- 命中还会看上下文，不是纯字符串匹配：
  - **否定**：「不讨厌」→ 翻到对立小类（喜爱）；「不开心」直接收在词表里
  - **程度**：「超级开心」升档，「有点开心」降档
  - **指向**：「你真烦」→ 这是在说她 → **受伤**；「领导骂我」→ 被欺负的是他 → **替他生气**；
    其余情况跟着对方的情绪走（情绪传染）

命中记录会落库（`mind.db` 的 `lexicon_hits` 表），面板「理论」页签里能看到热词和逐条明细。
不想要就在 `情绪 → 情绪评估 → 用中文情感词汇本体兜底` 关掉，或者把倍率调小。

## 🧠 记忆是怎么运作的

```
你说的话 ──┐
           ├─ 攒够 6 轮 或 静默 180 秒
她的回复 ──┘        │
                    ▼   交给模型抽取（只要 JSON，宁缺毋滥）
                    ▼   隐私判定 + 去重合并
              SQLite 记忆库
                    ▼   每轮按三路检索
              注入这一轮对话
```

| 来源 | 取什么 | 为什么需要 |
| --- | --- | --- |
| 📌 一直记得的 | 常驻档案（名字、生日、称呼、长期爱好、约定） | 否则她每次都像第一次见你 |
| 🕐 最近发生 | 最近 14 天内的记忆，最多 5 条 | 承接跨会话的短期上下文："他上周感冒了" |
| 🔎 可能和这轮有关 | 按 相关度 + 新鲜度 + 重要度 打分，取 top 4 | 从上百条旧记忆里捞出此刻用得上的 |

「可能和这轮有关」有两道硬门槛：**必须真的有关**（词法、关键词、语义至少命中一个），
以及**分数要够**（默认 0.22）。否则"新鲜 + 重要"两项会让无关旧事一直阴魂不散。

> 抽取时模型会给每条记忆产出 2~5 个关键词。这不是装饰：中文短句换个说法以后
> 字符二元组几乎对不上（"我家那只猫" vs "他养了一只叫团子的猫"），
> 关键词是唯一能把它捞回来的东西。

### 隐私（三道默认关闭的闸门）

1. **敏感识别**：证件号 / 手机号 / 长串数字 / 住址 / 学校 / 密码 → 标 🔒，
   唯一可见组合是「本人 + 私聊」，群聊永远不注入。
2. **作用域隔离**：群里学到的只在该群可用；私聊学到的默认不在群里注入。
3. **认不出就当群聊**：会话类型识别失败时按最保守处理。

## 🕸 记忆图谱

「长期记忆」是列表，「记忆图谱」是**一眼看出她脑子里那张网长什么样**。

面板 →「**记忆图谱**」页签。顶上六个数字：总记忆 / 图上 / 节点 / 关系 / 簇 / 活跃会话；
下面是一张力导向的活图，可以拖节点、滚轮缩放、拖空白平移，点实心圆看那条记忆的详情。

**多选管理**：点「多选管理」进入选择模式（这时拖不动节点，点了就是勾选），
被选中的圆会亮起绿圈。可以点单个节点、也可以**点簇的虚线圆圈整簇选中**，
然后批量：设为常驻 / 取消常驻 / 改作用域（本会话 / 本人 / 全局）/ 删除。
「全选」「清空选择」在旁边。走的是和「长期记忆」同一套批量接口。

### 节点和边是怎么来的

不额外抽取实体，全部**从已有数据里长出来**：

| 元素 | 是什么 | 画成 |
| --- | --- | --- |
| **记忆** | 抽取到的每一条事实 / 喜好 / 经历 / 约定 | 实心圆，越大越重要 |
| **关键词** | 那条记忆自带的关键词 | 浅色小点 |
| **人** | 记忆挂在谁身上（owner_id） | 方块 |
| **会话** | 记忆是在哪个群 / 私聊里学到的 | 三角 |

边有三种：记忆 → 关键词（has）、记忆 → 人（about）、记忆 → 会话（in）。

### 簇是怎么聚出来的

**拿关键词当桥**：两条记忆共享同一个关键词就被连起来，于是一整片相连的记忆自然成一簇
（虚线圆圈就是它的范围，标签写着 `C/01 · 12`，后面那个数是簇里有几条记忆）。

- 天天聊的那些会连成一个大簇；
- 某次旅行、某个人、某件特定的事会各自成小簇；
- 一个被几十条记忆共用的**高频词不会当桥**（否则整张图会被它拉成一坨）——
  阈值在 `mind/graph.py` 里的 `MAX_KEYWORD_FANOUT`。

这跟人记东西的方式其实挺像的：不是按时间排，是按"跟什么有关"挂在一起。

### 一些细节

- **布局在浏览器里算**：服务端只出节点和边，不掺和力导向，所以不会卡聊天；
- 能按**类型 / 作用域 / 最多画多少条**过滤，也可以只看常驻；
- 记忆越多，画面上限默认 260 条（可调到 800）—— 全都画上去浏览器会卡，
  而且本来也看不清；
- 图上不会出现别的东西：这是你库里真实的数据，不是装饰。

## 🖼 关键词配图

在面板的 **关键词配图** 标签页里上传图片，给它配几个触发词。
之后只要有人说中，她就会**直接把图发出去，不再走模型回复**（默认行为）。

### 三种匹配方式

| 方式 | 行为 | 例子 |
| --- | --- | --- |
| 包含关键词 | 消息里出现这个词就触发（默认，覆盖大多数场景） | 「我睡了晚安」命中「晚安」 |
| 完全等于 | 整条消息一字不差 | 只有「晚安」命中 |
| 模糊相似 | 按字符重合度算分，错别字和语序颠倒也能命中 | 「安晚」命中「晚安」 |

> 模糊匹配用的是**字符集合的 Jaccard**，不是二元组 —— 中文短词用二元组太苛刻，
> 「安晚」和「晚安」会一个二元组都对不上，而字符集合能拿到满分。
> 阈值默认 0.6：「晚安」对「晚安啦」是 0.67 通过，对「今天天气不错」是 0 拒绝。

### 几个细节

- **冷却时间**（默认 30 秒）：同一会话里同一个触发词短时间内只发一次，
  否则一句「晚安」刷十遍就变成刷屏机器了。
- **指令不会被截胡**：以 / # ! 等开头的消息按指令处理，不参与配图匹配。
- **只发图时情绪照常结算**：即使不回她，这句话也照样影响她的心情。
- **可以只对某个人生效**：作用范围选「只对某个用户」并填用户 ID。
- **可以附带一句话**：配置里填了「发图时附带的一句话」就会先发文字再发图。
- 支持**多选管理**：每张图前面有勾选框，配合「全选」一次选中多张，
  然后可以批量删除、批量启用/停用触发词、批量改匹配方式、批量改作用域。
- 图片存在 data/plugin_data/astrbot_plugin_ai_mind/images/，
  面板预览走 base64，不会往插件目录里写东西。

### 让 AI 自己决定什么时候发图

不只是「你说关键词她发图」—— 她自己也能决定发。被逗笑、想撒娇、生气的时候甩一张。

做法是：插件把**当前可用的图清单**注入系统提示词（不注入的话模型根本不知道有这回事），
她在回复里写标记，插件再把标记换成真正的图片：

```
她说：哼<pic>晚安</pic>我睡了
你收到：[文字「哼」] [图片] [文字「我睡了」]
```

支持两种写法：<pic>晚安</pic> 和 [pic:晚安]。

- 标记**无论如何都会从可见文字里摘掉**，用户永远看不到标记本身。
- 关键词对不上时，先模糊匹配触发词，再模糊匹配你给这张图写的**备注**。
- 一条回复最多发 2 张（可配），发多了很吵。
- 配置里「关键词配图 → 让 AI 自己决定发图」可以整个关掉。

> **为什么不做成函数调用？** 那要求模型支持 tools，而便宜的小模型大多不支持。
> 标记法任何模型都能用，而且和这个插件里已有的情绪标记是同一套机制。

## 🫧 拟人分段

人设里写着「最多 1~3 条气泡」，但模型不一定听话 —— 这一块负责兜底：
把一条回复按标点拆成几口气，**前面的用主动发送先吐出去，最后一段交回框架**，
中间按「下一口气有多长」插一段拟人停顿。

做法参考了 [astrbot_plugin_splitter](https://github.com/nuomicici/astrbot_plugin_splitter)，
重新实现后并进本插件：不用多装一个插件、不用多一份配置文件、共用同一块面板。

**为什么要「先发前面的、最后一段交回框架」**：`on_decorating_result` 只能改一条消息链，
没法让它变成两条。主动发送（`context.send_message`）才是唯一能在同一个事件里连续吐多条消息的口子；
把最后一段留在链里交回框架，引用回复、TTS、平台特有能力就都还走原来的路。

### 怎么切

- 默认按 **句号 / 问号 / 叹号 / 分号 / 省略号 / 换行** 切，正则可以在面板上改；
- **智能保护**开着时，这几样东西整块保留、绝不切碎：
  - 三个反引号围起来的代码块
  - `<think>...</think>`
  - Markdown 表格
  - 引号与括号里的内容（「……」、（……）、《……》）
- **均分长度**让每口气尽量差不多长，不会出现「嗯。」配一大段；
- **最多几口气**默认 3 —— 人设里那个上限就靠它兜底，多出来的内容并进最后一条。
- **不会用逗号断句**：均分模式需要在逗号处二次切分时，会**退回这一口气里最后一个句末标点**
  再切，找不到就干脆不切 —— 所以气泡不会以「，」结尾（早期版本会出现
  「下午好。晚上随便你，」这种看着像没打完的气泡）。

还有两个防呆：**短于 N 字不切**、**长于 N 字不切**（默认都是 0 = 不限）。

### 中间停多久

延迟按**下一段有多长**算 —— 下一口气越长，停顿越久：

| 策略 | 怎么算 | 什么时候用 |
| --- | --- | --- |
| `linear`（默认） | 基础值 + 字数 x 系数 | 通用 |
| `log` | 基础值 + 系数 x ln(字数+1) | 长段也不想等太久 |
| `random` | 在最小 ~ 最大之间随机 | 更像真人 |
| `fixed` | 固定值 | 调试，或者就想稳稳的 |

单段最长等待默认 4 秒封顶，免得一次回复卡半天。

### 在面板上调，不用改配置

面板 →「**分段拟人**」标签页，所有参数都能直接改，
**写完点「保存」立刻生效**，存在 `splitter_overrides.json` 里，重启也还在。

最关键的是中间那块「**试切一下**」：写一段她可能会说的话，点「试切」，
它会告诉你**会拆成几口气、每口气是什么、中间停几秒** —— 只算不发。
调参不用在群里试错。

改坏了点右上角「还原成配置文件」，面板上的改动全部丢掉，回到 `_conf_schema.json` 里的值。

### 剩下几个开关

- **只切 AI 的回复**（默认开）：指令回执、报错、插件自己发的提示不会被切开；
- **范围**：私聊群聊都切 / 只在私聊 / 只在群聊；
- **白名单 / 黑名单**：支持 `*` 通配，例如 `aiocqhttp:GroupMessage:*` 全都不切；
- **这些词前面不切**：填「宝宝」，就不会把「……哼。」和「宝宝你在干嘛」拆成两条；
- **发出去之前先替换**：一行一条 `被替换=>替换成`，右边留空就是删掉（例如清掉「作为AI」）；
- **图片怎么跟**：图片可以单独占一条、跟着下一段、跟着上一段，或者嵌在文字里。

### 语音（TTS）兼容

分段和语音插件很容易打架，这块专门治它。下面三个坑都是真的被刷屏刷出来的。

**坑一：语音插件念的是整条，分段却把文字切成了好几条。**
TTS 情绪路由那类插件会让模型在回复里写 `[TTS]` / `【语音】` 这类标记，
再拿**整条回复**去合成语音。一分段就变成「语音念一句 + 文字刷一片」，
而且标记本身还会被当正文发出去（因为语音插件只拿到最后一段）。
默认开着「回复里有语音标记就不分段」，命中了就整条交给它，标记列表可以自己填。

**坑二：TTS 插件把「整条文字 + 整条语音」一起塞进消息链。**
这是最常见的那种：语音念了一遍，同样的文字又分成三条冒出来。
默认策略是**仅发语音** —— 既然都念过了，重复的文字就不发了：

| 策略 | 你会收到 |
| --- | --- |
| `voice_only`（默认） | 只有语音 |
| `text_only` | 只有文字，语音丢掉 |
| `voice_then_text` | 先语音，再发一条完整文字（不拆分） |
| `both` | 文字照常分段 + 语音（旧行为，会刷屏） |

**坑三：框架内置语音开着的时候，最后一段会被框架单独转成语音。**
插件主动发出去的前几段**绕过**框架的语音转换，留给框架的尾段却会被转 ——
于是「前几段文字 + 最后一段语音」，一半一半。
这里的做法是：只要框架语音有可能生效，就**整条只掷一次概率、并且所有分段都由插件发完**
（尾段也不留给框架）。所以要么全是语音、要么全是文字，不会混。
某一段合成失败会自动退回发文字，不会把整条回复弄丢。

顺带说一句：如果你同时还开着 AstrBot 自带的「分段回复」
（`platform_settings.segmented_reply.enable`），那就是两套分段各切一次，
建议只留一套。

### 和别的分段插件冲突吗

如果同时还装着 `astrbot_plugin_splitter`，**两条流水线会各切一次**，气泡会被切得过碎。
二选一：要么在本插件配置里关掉「拟人分段」（`splitter.enabled = false`），
要么把那个插件停用。

## ⏱ 消息防抖

人说话是一句一句发的：「今天晚上」…「吃什么」…「好啊」。三条分开到她那里就是三轮调用 ——
她会在你说完第一句的时候就抢答。**消息防抖**把这种连发攒成一轮再交给她。

做法参考了 [astrbot_plugin_debounce](https://github.com/advent259141/astrbot_plugin_debounce)，
但判断核心换掉了 —— 原版下载一个微调过的模型（`onnxruntime` + `transformers` + `modelscope`）
来判断「说完了没」；本插件坚持零第三方依赖，改成**本地规则**：

| 这句话长什么样 | 怎么办 |
| --- | --- |
| 结尾是「。！」「吗」「吧」，或者已经超过 12 字 | 立刻发 |
| 短句、又没有句末标点（拿不准） | 等 1 个窗口 |
| 结尾是「，」「、」，或者停在「然后」「因为」这种连接词上 | 等 2 个窗口 |

等的时候用户补了新消息就**并进来**；并过的那条自己那一轮会被停掉，不会回两次。
合并时中文之间**不加空格** —— 加了就变成「今天晚上 吃什么」，一眼假。

**规则不如模型准，所以判不准的时候默认放行** —— 宁可早回一句，也不能把用户的话吞了。
等待有硬上限（默认 6 秒、最多合并 5 条），到点就发，不会一直吞着。

### 为什么不用「伪造事件」那套

原版的做法是：`stop_event()` 拦下消息 → 缓存 → 超时后**伪造一个消息事件回灌 EventBus** 补发。

这里换了个更简单的路子：**在 `on_llm_request` 里睡一个短窗口**。
AstrBot 的 `on_waiting_llm_request` 钩子在**会话锁之前**触发，
所以正在睡的那一轮能在这里看到「用户又补了一句」，醒来直接合并 ——
不用伪造事件，也没有缓冲区清空的竞态。

> 代价是这一轮会占着会话锁最多几秒。锁是按会话分的，不影响别的会话。

### 怎么开

**默认是关的** —— 它会给短消息加一点点延迟，这种「时间上的意外」不该默认塞给所有人。

面板 →「**消息防抖**」页签：一键开关 + **试判预览**（写一句话，看它是「立刻发」还是「先等一等」）。
参数在「上手 → 全部功能设置 → 消息防抖」里。

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `debounce.enabled` | false | 总开关 |
| `debounce.scope` | both | 私聊群聊都防抖 / 只在私聊 / 只在群聊 |
| `debounce.grace_seconds` | 1.5 | 一个窗口的长度 |
| `debounce.max_wait_seconds` | 6 | 一轮最多等多久（硬上限） |
| `debounce.max_messages` | 5 | 一轮最多合并几条 |
| `debounce.long_enough` | 12 | 超过这么多字就不等了 |

指令（以 `/` `!` `！` `#` 开头）永远不防抖。

## 把它发给别人 / 换成自己的人设

整个插件目录打包发给别人就行。**内置的傲娇预设是原样保留的**，
不管别人怎么改都动不到它（有测试锁着）。

> ⚠️ 对方装好之后**必须自己去面板上填「专属用户」**（他自己的 ID），
> 否则她不会认人 —— 这跟人设写得多详细没关系，是插件没被告知「谁是宝宝」。

### 别人怎么改成自己的人设

面板 →「人格定制」标签页。**默认只有两步**：

1. **她是什么性格** —— 温柔 / 傲娇 / 冷淡 / 活泼 / 毒舌 / 沉稳 / 忧郁，点一下定底色；
2. **她该怎么说话** —— 用大白话写一段，例如「嘴硬心软，句子很短，爱用『哼』」。

改完点「另存为」取个名字，再点「应用」立刻生效（不用重启）。
那段大白话会作为 `<persona_style>` 直接进提示词，是**最有效的定制手段**。

右上角「显示高级选项」里还有：

| 改什么 | 说明 |
| --- | --- |
| 基础数值 | 愉悦 / 唤醒 / 掌控 三条基线，以及情绪半衰期、心境半衰期、好感度初始值 |
| 表达基调 | 23 种情绪逐条「该怎么说话」——想精细控制每种情绪的口气时用 |
| 自定义规则 | 一行一条的触发规则，和你现在用的格式一样 |

### 预设怎么分享

- **导出**：在人格定制页点「导出 JSON」，把内容复制走；
- **导入**：把别人的 JSON 粘进同一个框，点「导入 JSON」；
- 也可以直接把自己数据目录下 `presets/<名字>.json` 发给他。

> 预设文件存在 `data/plugin_data/astrbot_plugin_ai_mind/presets/`，
> 是普通 JSON，手改也行。内置的 `tsundere` / `neutral` 不能覆盖，
> 想基于傲娇改就先导出它、改完另存为新名字。

## 删除按钮为什么要按两次

面板跑在沙箱 iframe 里，浏览器会**静默拦掉** `window.confirm()` 这类模态框
（直接返回 false）。于是代码停在 `if (!confirm(...)) return;` 那一行：
点了没反应，也不报错 —— 面板里每一个破坏性操作都踩过这个坑。

所以现在改成**两步确认**：第一次点会提示「再点一次确认」，五秒内再点一次才真的执行。
不想这样也可以等五秒让它自己失效。

## 面板加载失败怎么办

面板跑在**不透明源的沙箱 iframe** 里，自己发 `fetch` 会被判成跨域失败，
所以必须走宿主注入的 postMessage 桥。而桥接受的端点前缀在不同 AstrBot 版本里不一致，
因此页面第一次加载时会**把候选地址逐个试过去**：

```
<子路径>                         （空前缀：插件名由宿主自己补，实测 v4.28.1 就是这种）
<插件名>/…                       （宿主只补 /api/plug/）
/api/plug/<插件名>/…             （宿主原样发出）
/plugins/extensions/<插件名>/…    （新版路由，宿主补 /api）
/api/plugins/extensions/<插件名>/…
/plug/<插件名>/…                 （宿主补 /api 的另一种约定）
```

每种各试一次「走桥」和「直接 fetch」，谁先返回正常数据就用谁，之后固定下来（共 10 种组合）。
页面顶部会显示一行状态：

- **接口正常：bridge → /api/plug/…** —— 一切正常。
- **接口不通 —— …** —— 所有组合都失败了，后面逐条列出失败原因。
  把这一行截图就能定位问题；通常是 AstrBot 版本差异，或者面板还没登录。

后端这边也做了三件事，尽量让「匹配不上」这件事不要发生：

1. **GET 和 POST 都注册**。AstrBot 的路由匹配会**先看 HTTP 方法** ——
   只注册 GET 的话，宿主一旦用 POST 发，请求就会直接落进「未找到该路由」。
2. **两个命名空间都铺**：插件目录名，以及 AstrBot 内部的 `plugin_id`（作者/插件名）。
3. **兜底路由**：命名空间下没直接匹配上的路径会落到兜底处理函数 ——
   它把宿主真实发的路径写进日志（`[ai_mind] 面板收到未直接匹配的路径：…`），
   并按后缀把请求分发给正确的接口。

另外有一个人工自检接口 `/<插件名>/_echo`，
会把后端看到的路径、方法、参数原样返回，用来确认桥到底把请求发到了哪里。

## 已知限制

- **面板接口跟着 WebUI 的登录态走**。默认只有能登录 AstrBot 面板的人能用；
  它不是面向公网开放的接口。
- **危机识别是规则式的**，会有漏判（反讽、隐喻、间接表达都可能漏）。
  它给人设兜底，**不能替代真正的危机干预**。
- **情绪由规则驱动，不理解语义**。"你可真厉害"这种反讽会被当成夸奖，
  可以在 `情绪 → 人格 → 自定义情绪规则` 里补充你圈子里的说法。
- **记忆抽取质量取决于你配的模型**；去重是词法级的，高度重写过的同一件事可能存成两条。
- **缓存中未抽取的对话不持久化**，重启会丢掉最多一个批次（约 6 轮）的待抽取内容。
- 记忆只看文本，不处理图片与语音。

情绪部分的理论依据：

- **PAD 三维情感模型**（Mehrabian）—— 愉悦（Pleasure）/ 唤醒（Arousal）/ 掌控（Dominance）
- **Plutchik 情绪轮** —— 8 条基本情绪轴 + 4 对反义轴
- **大连理工情感词汇本体库** —— 中文情感词表；本插件内置其中 845 条常用口语词作为规则兜底

> **关于分段模块的再分发**：`mind/splitter.py` 是把 splitter 的功能在本项目内重新实现，
> 以便与情绪/记忆共用同一份配置和面板。splitter 仓库目前**未声明许可证**，
> 如果你打算二次分发本插件，建议先与原作者确认。
